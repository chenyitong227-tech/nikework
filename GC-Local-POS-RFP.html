Section 1

1引言 · Introduction

1.1目的与范围 Purpose & Scope

本 RFP 旨在为 Nike 中国大陆（Mainland China）遴选并建设本地 POS 系统，覆盖 NPOS Mobile（手持）、NPOS Fixed（固定收银）两种形态；币种（CNY / 人民币）、税务/发票（E-Fapiao）、支付方式与合规按中国大陆要求本地化实现。

本文件构成：§2 主数据需求——商品、价格、折扣/促销、员工、员工折扣、库存、门店、会员、Non-Merch、订单、原因码 十一个数据域，以及 §2.12 系统对接图；§3 场景化需求——§3.1–3.12 端到端销售场景（普通商品、会员、NBY 与 Non-Merch、Swoosh 员工、FF Card 亲友卡、Comp 工服、Gift Card、@Wo 远程、门店数字销售 DSIS、门店取货 BOPIS、退换货、自助结账），§3.13–3.21 跨场景通用能力（支付、收据与发票、登录、现金管理、员工维护、电子日志 WebEJ、SOR 报表清单、硬件外设、离线连通）。

1.2需求编写约定 Requirement Conventions

每条需求均带唯一编号与优先级，以便追溯与后续供应商逐条应答。编号规则：

主数据MD-<域>-NN，如 MD-PRD-01（商品）、MD-PRC-01（价格）、MD-PROMO-01（折扣/促销）、MD-EMP-01（员工）、MD-EDISC-01（员工折扣）、MD-INV-01（库存）、MD-STR-01（门店）、MD-MBR-01（会员）、MD-NM-01（Non-Merch）、MD-ORD-01（订单）、MD-RSN-01（原因码）
场景需求SC-<场景>-NN（销售场景），如 SC-STD-01（普通商品）、SC-NBY-01（NBY）、SC-SWO-01（Swoosh 员工）、SC-COMP-01（Comp 工服）、SC-GC-01（Gift Card）、SC-WO-01（@Wo 远程）、SC-DSIS-01（门店数字销售）、SC-RET-01（退换货）；OP-<域>-NN（跨场景通用能力），如 OP-PAY-01（支付）、OP-RCP-01（收据）、OP-LOG-01（登录）等

1.3优先级定义 Priority Definitions

Must功能对齐（Feature Parity）基线。凡 1POS Fixed / NPOS Mobile 现有能力一律为 Must；上线（Go-Live）前必须满足，未满足即视为不合规、功能回退。
Should拓展 / 超越对齐需求（Beyond-Parity）。源自 4 阶段 roadmap 与 GC Confluence scope 的增强项；应当满足，可分阶段（Pilot→Scale）交付，需说明计划与影响。
Nice可选 / Stretch。roadmap 中的 Stretch 或增值项；在能力允许时提供。

Section 2 · Master Data Requirements

2主数据需求 · Master Data Requirements

主数据是 POS 一切交易、定价、促销、结算、报表的基础。下表按数据域列出：数据元素 → 来源系统 → 依赖分类 → 优先级 → 对接方式 → 消费场景。来源系统映射自 NPOS 依赖树与 Solution 架构。

基线原则：本地 POS 无论采用「系统对接」或「自建 Checkout」，A 类主数据（商品/价格/促销/会员/库存/门店配置/鉴权）都必须持续从公司企业主数据获取；B 类（编号/原因码/Non-Merch配置/发票配置）可本地维护；对下游守住 POSLOG 契约即可最小化改造。
